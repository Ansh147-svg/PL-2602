What is CI & CD?
CI - Continuous Integration
	Hotstar	----> Version1.0	----> Test the code		----> Build the code
	Hotstar	----> Version1.1	----> Test the code		----> Build the code
	Hotstar	----> Version1.2	----> Test the code		----> Build the code

CI = CT + CB

CD - Continuous Delivery
	If you are manually deploying the code into the servers, that is known as Continuous Delivery

CD - Continuous Deployment
	If you are automating the process of building the code, testing the code, and deploying the artifact

Stages in CI & CD process;

Pre-requisite: Setup the infrastructure (Creation of EC2 Instances) and install CI & CD tool (Jenkins)

Stage 1: get the code from the GitHub repo
Stage 2: build the code (artifacts)
Stage 3: store the artifact (Nexus, JFrog, S3 Buckets...)
Stage 4: code quality analysis (SonarQube)
Stage 5: build the docker image (Docker)
Stage 6: scan the docker image for vulnerabilities (Trivy, Docker scout image analysis, owasp...)
Stage 7: deploy the app	
			7.1. Tomcat webserver
			7.2. Docker container
			7.3. Kubernetes cluster

=> Jenkins Jobs
What is a job?
Job is a collection of multiple tasks

Jenkins has 2 types of jobs;
Freestyle Project	- any configuration related to a Jenkins job will be done by using Jenkins UI
Pipelines			- the configuration of Jenkins job will be done by using scripting
	multi-branch pipeline

*Pipelines are preferred for app deployments in real-time

=> Jenkins Parameters - Parameterized Jobs
What is a parameter?
Parameters are used to pass the variables in the form of key-value pairs during the build process

Types of parameters;
String	- group of characters
Choice	- select an option from the list of choice
Boolean	- true / false
