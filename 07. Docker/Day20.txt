=> Dockerfile
To automate the image creation
Dockerfile will work as configuration file to create docker images. By using the docker images, which are created by using Dockerfile, we can create custom containers with our own application

Dockerfile has DSL key-words
DSL - Domain Specific Language

All the DSL key-words must be written in CAPITAL letters only
Every DSL key-word should be written in a new line

Dockerfile Components;
1. FROM
It indicates the base image to run our application
On top of base image, we will create our own images
Every new base image should be configured in a new line

FROM ubuntu 
FROM tomcat
FROM MySQL
FROM python
FROM jdk
FROM maven

2. RUN
It is used to execute the commands "while creating the docker image", on top of base image
We can write multiple RUN instructions in a single Dockerfile.
Docker engine will process the instructions from TOP to BOTTOM

RUN touch kastro.java
RUN mkdir docker
RUN yum install git -y

3. CMD
It is used to execute the commands "while creating the docker container"
We can write multiple CMD instructions in a single Dockerfile, but only the last CMD instruction in the Dockerfile will get processed 

CMD touch kastro.java
CMD mkdir docker
CMD yum install git -y ---> This will be processed by Docker

There is no point in writing multiple CMD instructions in a single Dockerfile


FROM ubuntu #will pull ubuntu image from docker-hub
RUN apt update -y
RUN apt install git -y
RUN touch kastro.txt


FROM ubuntu
RUN apt update -y
CMD apt install maven -y
RUN apt install git -y
CMD mkdir docker-day2
RUN touch kastro.txt

4. COPY
It is used to copy the files/directories to a docker images while creating the image
It is also used to copy the files from source location to destination location
It is also used to copy the files from VM to container

5. ADD
It is also used to copy the files/directories from source location to destination location
By using ADD we can download the files from internet using the URL

6.WORKDIR
By default, when we login to the container we will be there in the root path (/) of the container
All the instructions that are written after WORKDIR instruction will be executed in the WORKDIR location only

FROM ubuntu
RUN apt update -y
RUN apt install git -y
RUN touch kastro.txt
WORKDIR /tmp
RUN touch docker.py
RUN mkdir python-dir

7. LABEL
It is used to assign metadata for our image
key-value pair

FROM ubuntu
RUN apt update -y &&  apt install git -y && apt install maven -y
RUN touch kastro.txt
WORKDIR /tmp
RUN touch docker.py
RUN mkdir python-dir
LABEL author Kastro
LABEL app netflix
LABEL env prod

Note: We can use && to execute multiple commands within a single Dockerfile instruction

CMD ["bash"]

8. ENV
It is used to set the environment variables inside the container
key-value

FROM python:3.10
WORKDIR /app
COPY app.py .
ENV APP_ENV=dev-env
ENV APP_PORT=5000
ENV APP_NAME=Netflix
CMD ["python", "app.py"]

To overwrite the above values, we can use docker run -e APP_ENV=prod-env image3:v2
Now you will see the overwritten value. This overwritten is the default behaviour of CMD Instruction

Note: CMD instructions can be overwritten

9. ENTRYPOINT
ENTRYPOINT instructions cannot be overwritten

10. EXPOSE
It is used to expose our application to the end users

11. USER
By default the docker containers will run as "root" user only
In real-time we should never run the containers as a root user
Always run the containers as non-root user

12. MAINTAINER
It  represents author/maintainer of the Dockerfile

FROM ubuntu
EXPOSE 8080
MAINTAINER name kastro

13. VOLUME
It is used to store data or mount the storage to the container
