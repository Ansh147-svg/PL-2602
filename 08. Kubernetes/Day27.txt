=> Blue-Green Deployment
Blue Version		- Old version		- currently deployed
Green Version	- New version	- need to deploy the latest version

# 🔵 Blue Deployment (Version 1 - Stable Release)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-blue
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
      version: blue
  template:
    metadata:
      labels:
        app: nginx
        version: blue
    spec:
      containers:
      - name: nginx
        image: nginx
        ports:
        - containerPort: 80
        command: ["/bin/sh"]
        args:
          - "-c"
          - |
            echo '<html><body style="background-color:skyblue;">
            <h1>YouTube/LearnWithKASTRO</h1>
            <h2>This is BLUE (Version 1)</h2>
            </body></html>' > /usr/share/nginx/html/index.html && nginx -g "daemon off;"

✔ LoadBalancer Service (Initially points to BLUE)
service-bluegreen.yaml

# 🌐 LoadBalancer Service
# Initially routes ONLY to the BLUE version (v1)
apiVersion: v1
kind: Service
metadata:
  name: nginx-lb
spec:
  type: LoadBalancer
  selector:
    app: nginx
    version: blue   # ← Switch this later to "green" for release
  ports:
  - port: 80
    targetPort: 80


Limitations:
If the new version of the application, wont respond, ALL the end users will get affected at a time

=> DaemonSet
DaemonSet will ensure only one pod is running on one worker node, related to the same application
Worker Node 1 - 1 pod

=> Pod Scheduling Strategies
To control pod placement on a specific worker node(s), we will use pod scheduling strategies
Node Selector	- simplest
Node Affinity	- flexible - advanced features
Pod Affinity/Anti-Affinity - flexible - advanced features
